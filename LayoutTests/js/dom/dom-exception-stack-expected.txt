DOMException has the [[ErrorData]] internal slot, and its JS wrapper is a JSC ErrorInstance, so it exposes the same non-standard stack/line/column/sourceURL properties that a plain Error does. This matches Firefox (which also reports a stack for DOMException) and is what the WebIDL web-platform-test "If the implementation has a stack property on normal errors, it also does on DOMExceptions" requires. This test can be run directly in any browser to compare behavior.
