Tests that the 'size' shorthand is parsed but never generated during serialization, so copied and pasted markup stays compatible with engines and older WebKit that do not support it yet. See https://bugs.webkit.org/show_bug.cgi?id=289633

On success, you will see a series of "PASS" messages, followed by "TEST COMPLETE".


Longhands do not collapse into the size shorthand during serialization:
PASS element.style.cssText is "width: 100px; height: 200px;"
Equal width and height do not collapse either:
PASS element.style.cssText is "width: 50px; height: 50px;"
The size shorthand still expands to the width and height longhands:
PASS element.style.getPropertyValue('width') is "100px"
PASS element.style.getPropertyValue('height') is "200px"
Content authored with size serializes back as longhands, not as size:
PASS element.style.cssText is "width: 100px; height: 200px;"
The size shorthand is still available when explicitly requested:
PASS element.style.getPropertyValue('size') is "100px 200px"
PASS successfullyParsed is true

TEST COMPLETE
