Cases

Serve this page over HTTP, for example from the OpenSource checkout: python3 -m http.server 8000 --bind 0.0.0.0, then open http://<host>:8000/ManualTests/media/remote-playback-routing.html. By default both videos are Apple's public HLS sample streams, which the receiver loads directly. Use ?first=<url>&main=<url> to try other media; the receiver must be able to load them. ?scenario=muted-loop&autoplay sets up on load and autoplays the first video without a user gesture, as on apple.com; the other scenario values are disableremoteplayback, x-webkit-airplay-deny, x-webkit-wirelessvideoplaybackdisabled and none.

A video is on the route when its isWireless marker is shown, and the receiver shows that video.

  1. Route active before the first video plays. Connect the route (iOS: AirPlay from Control Center, or the casting app for a MediaDeviceRoute; macOS: AirPlay from Control Center or the menu bar). Pick a first-video option, Set up, Play first video, then Play main video. Note which video goes to the receiver, and when. Repeat with ?scenario=muted-loop&autoplay, loading the page after the route is connected, so the first video starts without a tap.
  2. Route connected during playback. Set up, Play first video, Play main video, then connect the route.
  3. Opt-out added while on the route. Choose "Unmuted, no opt-out", Set up, connect the route, Play first video and wait for it to reach the receiver. Then Add opt-out to first video. Note whether it comes back to local playback, pauses, or errors.
  4. Opt-out removed. After case 3, Remove opt-out from first video. Note whether it goes back to the receiver.
  5. macOS picker. With nothing connected, Set up, Play first video, then pick a device from the AirPlay button in the main video's controls. Note which video goes to the receiver.
